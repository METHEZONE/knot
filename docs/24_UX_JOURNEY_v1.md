# KNOT UX 여정 v1 — 두 창, 두 사용자, 각자의 채팅창

**결정 주체:** 민성 (2026-07-27 인터뷰)
**상태:** 승인 — 프론트 구현 기준
**대체 관계:** `PLANS.md`의 Product MVP Frontend Plan을 이 문서가 구체화한다.
라우트 맵과 프라이버시 규칙은 유지하고, 화면 수와 인터랙션을 여기서 확정한다.

## 0. 이 문서가 정하는 것

데모는 **브라우저 창 두 개를 좌우로 띄워** 크리에이터와 브랜드를 동시에
보여준다. 그러므로 모든 화면은 "이 창의 주인에게 보이는 것"으로만 설계한다.
세션은 창 단위(`sessionStorage`)이고, 상대 역할 화면은 열리지 않는다.

설계 원칙 하나: **사람이 신경 쓸 것을 최소화한다.** 입력은 역할당 2~3개,
승인은 0회, 화면은 역할당 3개다. 그 이상은 이 데모에서 값을 만들지 못한다.

## 1. 확정 사항 (인터뷰 결과)

| 항목 | 결정 |
|---|---|
| 크리에이터 플랫폼 | **인스타그램만.** 유튜브·X·틱톡은 v1 제외 |
| 인스타 연결 | **사용자이름 입력 → 사전 수집 리플레이.** OAuth 없음. `captured {date}` 라벨 필수 |
| 크리에이터 입력 | **마지노선(최저 단가) + 안 하는 카테고리**, 딱 둘 |
| 브랜드 입력 | **제품 링크**(자동 추출) + **릴스 10개 스와이프로 무드** + **예산/딜당 한도** |
| 스와이프 역할 | **온보딩에서 무드를 정한다.** 에이전트 탐색 기준이 되고, 이후 사람은 후보를 고르지 않는다 |
| 사람 승인 | **0회.** 설정 후엔 지켜보기만. 한도를 넘을 때만 에이전트가 물어본다 |
| 협상 표시 | **실시간 진행.** 타이핑 인디케이터, 라운드가 눈앞에서 쌓인다 |
| 홈 화면 | **내 에이전트와의 1:1 채팅창.** 에이전트끼리의 원문은 인용 버블을 펼쳐서 본다 |
| 에이전트 말투 | **정장 입은 사회자 + 유머 한 스푼.** 존댓말, 성격은 보이되 가볍지 않게 |

## 2. 화면 목록 (전체 7개)

```text
/login                    역할 선택 = 이 창의 로그인

크리에이터
/creator/connect          인스타 사용자이름 → 분석 카드
/creator/rules            마지노선 + 안 하는 카테고리
/creator                  내 에이전트 채팅창 (홈)

브랜드
/brand/product            제품 링크 → 자동 추출 확인
/brand/mood               릴스 10개 스와이프
/brand                    내 에이전트 채팅창 (홈)
```

브랜드의 예산/딜당 한도는 별도 화면을 만들지 않고 `/brand/mood` 마지막
단계에 붙인다 — 화면을 하나 더 늘릴 만한 무게가 아니다.

기존 `/brand/negotiate`·`/creator/result`·`/*/settlement`·`/*/me`·`/*/settings`·
`/dev/admin`은 **홈 채팅창 안으로 흡수**한다. 정산·마일스톤·계약서는 채팅
안에서 카드로 뜨고, 별도 페이지로 이동하지 않는다. `/dev/admin`만 운영용으로
남기되 상단바에서 감춘다.

## 3. 크리에이터 여정

### 3-1. `/creator/connect` — 인스타 연결

- 입력 하나: `@사용자이름`. 붙여넣기만 하면 된다.
- 누르면 에이전트가 분석하는 연출(2~3초) 후 **분석 카드**:
  팔로워, 평균 조회수, 참여율, 잘 먹히는 포맷(릴스 비중), 톤 키워드,
  그리고 **추천 마지노선 범위**.
- 카드 우상단에 `2026-07-26 수집` 배지. 그 아래 한 줄:
  "숫자는 수집된 게시물에서 계산했고, 문장만 AI가 씁니다."
- 이 화면에서 사람이 판단할 것은 없다. "맞아요, 계속" 하나.

### 3-2. `/creator/rules` — 두 개만 정한다

- **마지노선**: 숫자 하나. 추천값이 미리 채워져 있다.
  아래 한 줄: "이 밑으로 들어오는 제안은 매니저가 알아서 거절해요."
- **안 하는 카테고리**: 칩 토글 (도박 · 대출/코인 · 다이어트 보조제 ·
  의료 시술 · 주류 · 성인). 기본 3개 선택.
  아래 한 줄: "돈은 협상해도, 이건 협상하지 않아요."
- 완료 → 매니저 부화 짧은 컷 → `/creator`

### 3-3. `/creator` — 내 매니저 채팅창

크리에이터가 앞으로 머무는 유일한 화면.

```text
┌─ Mina Agent ─────────────────────────┐
│                                       │
│  Mina Agent                           │
│  안녕하세요. 이제 제가 제안을 받을게요.  │
│  마지노선 650, 안 하는 건 3개 기억했습니다.│
│                                       │
│  Mina Agent                    ● 지금  │
│  Glow Bar Labs에서 제안이 왔어요.       │
│  ╭─────────────────────────────────╮ │
│  │ 릴스 1개 · 520 USDC             │ │
│  │ 마지노선보다 130 낮아서 역제안했어요 │ │
│  │ ▸ 협상 대화 보기          2라운드 │ │
│  ╰─────────────────────────────────╯ │
│                                       │
│  Mina Agent                           │
│  650으로 맞췄습니다. 계약할까요?  ← 아니, │
│  이건 안 묻는다 (승인 0회). 아래 참조.   │
└───────────────────────────────────────┘
```

- 사람에게 묻지 않는다. 매니저는 **결과를 보고**한다:
  "650으로 합의했고 계약서에 서명했어요. 첫 정산 195 USDC 들어옵니다."
- 인용 버블 `▸ 협상 대화 보기`를 누르면 그 자리에서 펼쳐지고,
  에이전트끼리 주고받은 원문이 실시간으로 흐른다(§5).
- 계약·정산은 채팅 안 카드로: 합의 카드 → 에스크로 잠김 카드 →
  마일스톤 카드(게시물 URL 제출 버튼 포함) → 정산 완료 카드.

## 4. 브랜드 여정

### 4-1. `/brand/product` — 링크 하나

- 입력 하나: 제품 URL.
- 붙여넣으면 자동 추출: 제품명, 가격, 대표 이미지, 한 줄 설명, 카테고리.
- 사람은 확인만 한다. 틀린 필드는 그 자리에서 수정 가능하되,
  **아무것도 고치지 않아도 넘어갈 수 있어야 한다.**

### 4-2. `/brand/mood` — 릴스 10개 스와이프

이 데모에서 브랜드가 하는 가장 재미있는 행동이고, 동시에 진짜 입력이다.

```text
┌─ 어떤 무드가 좋으세요? ───────────┐
│              3 / 10                │
│   ╭────────────────────────╮      │
│   │  [릴스 샘플 자동 재생]      │      │
│   │  잠자기 전 루틴            │      │
│   │  차분함 · 설명형 · 클로즈업  │      │
│   ╰────────────────────────╯      │
│      ✕ 아니야       ♡ 이런 느낌      │
│                                    │
│  고른 무드: 차분함 · 설명형 · 루틴    │
└────────────────────────────────────┘
```

- 좌우 스와이프(드래그) + 키보드 ←/→ 둘 다 지원. 10장 끝.
- 각 카드는 태그를 갖고, 좋아요한 카드의 태그가 **무드 프로필**이 된다.
  이게 에이전트의 탐색 기준이다 — 사람이 크리에이터를 고르는 게 아니다.
- 마지막 11번째 카드에 예산 두 개:
  **총 예산**과 **딜당 한도**. 딜당 한도 아래 한 줄:
  "매니저가 한 건에 800 USDC까지는 물어보지 않고 씁니다."
- 완료 → 매니저 부화 짧은 컷 → `/brand`

### 4-3. `/brand` — 내 매니저 채팅창

크리에이터 쪽과 대칭이다. 매니저가 진행상황을 말하고, 인용 버블로
협상 원문을 펼쳐볼 수 있다.

```text
Glow Agent
차분한 설명형 루틴 무드로 3명 추렸어요.
Mina Studio가 릴스 전환이 제일 좋습니다.
╭──────────────────────────────╮
│ Mina Studio · 적합도 94       │
│ ▸ 협상 대화 보기       2라운드 │
╰──────────────────────────────╯

Glow Agent
650에 합의했습니다. 한도 800 안이라 제가 서명했어요.
에스크로에 650 잠갔고, 게시물 확인되면 455 나갑니다.
```

- 브랜드 화면에만 적합도 점수와 딜당 한도가 보인다.
- 크리에이터의 마지노선과 안 하는 카테고리는 **절대 보이지 않는다.**
  반대도 같다. (`PLANS.md` 프라이버시 규칙)

## 5. A2A 협상 — 실시간, 그리고 구경할 맛

인용 버블을 펼치면 열리는 영역. 양쪽 창에서 동시에 같은 내용이 흐른다.

- 상대 에이전트 이름 + 타이핑 인디케이터(`● 입력 중…`)로 실시간 느낌을 만든다.
- 한 라운드에 한 발언. 발언마다 **금액 배지**와 **근거 한 줄**이 붙는다.
- 라운드 카운터 `2 / 5`. 5라운드에서 끊는다.
- 정책이 막는 순간은 빨간 도장으로 대화 사이에 끼어든다:
  `정책 차단 — 딜당 한도 800 USDC 초과`
- 숫자는 전부 결정론적 계산이다. 대사만 캐릭터가 있고, 금액·라운드·정산은
  엔진 값을 그대로 쓴다. **대사가 숫자와 다른 말을 하면 버그다.**

### 말투 규칙

정장 입은 사회자 + 유머 한 스푼. 존댓말, 짧은 문장, 사람 대신 협상하는
사람의 태도. 이모지는 발언당 최대 1개, 없어도 된다.

허용:
> "520이면 저희 쪽 기준선 아래예요. 650으로 맞춰주시면 오늘 바로 도장 찍습니다."
> "예산이 800까지라, 650은 제가 결정할 수 있는 범위입니다."
> "그건 제 권한 밖이에요. 사람한테 물어봐야 하는데, 아마 안 될 겁니다."

금지:
> "ㅋㅋ 콜?" (반말·초성)
> "이 제품은 혁신적인 솔루션으로서" (피치덱 말투)
> "AI로 분석한 결과" (자기 설명 — 그냥 결과를 말한다)

### 대사 대본 (합의 경로, 기본 시드)

| 라운드 | 화자 | 대사 | 배지 |
|---|---|---|---|
| 1 | Glow Agent | 릴스 1개에 520 USDC로 시작해볼게요. | 520 USDC |
| 2 | Mina Agent | 520은 기준선 아래예요. 650이면 이번 주에 찍습니다. | 650 USDC |
| 3 | Glow Agent | 650은 제 권한 안입니다. 그 금액으로 하죠. | 합의 |

### 대사 대본 (정책 차단 경로 — 마지노선 > 딜당 한도)

| 라운드 | 화자 | 대사 |
|---|---|---|
| 1 | Glow Agent | 릴스 1개에 640 USDC 어떠세요? |
| 2 | Mina Agent | 저는 1,200부터예요. 조정은 어렵습니다. |
| — | 정책 | **정책 차단 — 딜당 한도 800 USDC 초과** |
| 3 | Glow Agent | 여기까지가 제 권한이에요. 이번 건은 접겠습니다. |

이 두 경로는 사람이 넣은 숫자로 갈린다. 심사위원이 마지노선을 올려
결렬을 직접 만들어볼 수 있어야 한다 — 자율성의 경계를 말이 아니라
조작으로 보여주는 장치다.

## 6. 정직성 (변경 없음)

- 수집 데이터는 `captured {date}`. 라이브 스크래핑을 암시하지 않는다.
- `SIMULATED` 영수증(서명 null)은 시뮬레이션으로 표시하고 explorer 링크를
  만들지 않는다. 실제 devnet 서명이 있을 때만 링크한다.
- 수수료 라인은 어디에도 없다 (fee = 0 불변식).
- 숫자는 ingest/엔진에서 나오고, AI는 문장만 쓴다.

## 7. 이 문서가 버리는 것

- 유튜브·X·틱톡 연결, 진단 카드의 상세 지표 덤프
- Agent Society Map, 별도 협상 시어터 페이지, 공개 리플레이 페이지
- 5단계 위저드, 자율성 다이얼 여러 개, 역할 스위처, 알림 벨
- `/me`·`/settings`·역할별 대시보드 (채팅창이 대신한다)

버린 것들은 지우기 전에 `17_DEMO_ACCEPTANCE.md`의 하드 게이트와 대조해야
한다. 후보 3명·정책 차단·계약 해시·devnet 서명·증빙 판정은 게이트이므로,
채팅창 안 카드로 **반드시 남아야 한다.**
