# KNOT — 프로젝트 소개서용 블록체인 내러티브

작성: 효창(블록체인 레인) / 2026-08-02
용도: 제출 소개서·발표 스크립트에 그대로 옮겨 쓸 수 있는 서술. 각 문단은 코드로 뒷받침되는 사실만 담았고, 아직 증명되지 않은 항목은 §6에 따로 분리했다.

---

## 1. 한 문장

**KNOT은 브랜드 에이전트와 크리에이터 에이전트가 사람 없이 협상하고, 사람 없이 정산하는 플랫폼이다. 블록체인은 그 "사람 없음"을 신뢰할 수 있게 만드는 유일한 방법이라서 쓴다.**

---

## 2. 왜 블록체인인가 — 에이전트에게는 은행 계좌가 없다

인플루언서 마케팅의 실제 병목은 매칭이 아니라 **정산**이다. 브랜드는 콘텐츠가 실제로 올라갈지 모르는 채로 선입금하기 싫고, 크리에이터는 콘텐츠를 올리고도 돈을 못 받을까 봐 계약서를 원한다. 그래서 이 시장에는 항상 사람이 낀다 — 대행사, 계약서, 세금계산서, 정산 담당자.

에이전트를 도입해서 협상을 자동화해도 이 병목은 그대로 남는다. **자동으로 합의했는데 정산은 사람이 하는 시스템은 자동화된 게 아니다.**

여기서 문제가 하나 더 생긴다. 에이전트가 실제 거래를 실행하려면 단순 추천을 넘어 비용 집행과 조건부 지급까지 다뤄야 한다. 기존 송금 흐름만으로는 예산 한도, 증빙 확인, 자동 정산을 한 타임라인에서 다루기 어렵다. 그래서 프로그램이 검증할 수 있는 지갑과 자산 흐름이 필요하다.

그게 정확히 블록체인 지갑이다. KNOT이 온체인을 쓰는 이유는 "web3라서"가 아니라, **에이전트에게 결제 능력을 주는 다른 방법이 없어서**다.

---

## 3. 세 겹의 구조

KNOT의 온체인 설계는 세 겹이고, 각각 다른 문제를 푼다.

### (1) 합의를 위조 불가능하게 — Agreement 해시

에이전트끼리 협상한 결과는 최종적으로 하나의 Agreement Artifact가 된다. 이 합의 조건을 정규화해서 SHA-256으로 해시하고(`hashVersion: knot.agreement-terms.v1`), 그 해시를 정산 검증의 기준으로 사용한다.

효과는 단순하다. 나중에 누구도 "우리가 합의한 조건은 그게 아니었다"고 말할 수 없다. 에스크로 생성 시점에 해시가 검증되고, 불일치하면 `TERMS_HASH_MISMATCH`로 거절된다. 사람이 계약서를 보관하는 대신, **체인이 합의를 보관한다.**

### (2) 돈을 조건부로 묶어둔다 — Anchor 마일스톤 에스크로

브랜드의 USDC는 합의 후 에스크로 vault에 잠긴다. 이 돈은 브랜드도 크리에이터도 임의로 가져갈 수 없다. 약속된 조건이 충족되고 검증이 끝났을 때만 마일스톤 단위로 지급된다.

- 브랜드 입장: 콘텐츠가 안 올라가면 돈이 안 나간다. 선입금 리스크가 사라진다.
- 크리에이터 입장: 돈이 이미 잠겨 있는 걸 온체인에서 직접 확인할 수 있다. 미수금 리스크가 사라진다.

양쪽이 서로를 믿을 필요가 없어진다. **대행사가 하던 일을 프로그램이 대신한다.** 마일스톤 표준 프로그램이 없어서 Anchor로 직접 구현했고, 플랫폼 수수료(bps)도 릴리즈 시점에 USDC로 자동 분배된다.

### (3) Agent 운영 비용과 Creator 보상금을 분리한다 — x402 / pay.sh

협상과 정산 사이에는 "이 크리에이터가 진짜인가", "콘텐츠가 실제로 게시됐는가" 같은 **확인 비용**이 있다. 이 확인에는 유료 API가 필요하다.

여기서 중요한 것은 외부 검증 API 비용과 Creator 보상금을 섞지 않는 것이다. KNOT은 Agent 운영 결제에는 x402 / pay.sh를 사용하고, Creator 보상에는 별도의 에스크로 레일을 사용한다.

무제한 자율이 아니다. 지출은 세 겹의 상한 안에서만 일어난다 — 호출당(`PAYSH_MAX_CALL_AMOUNT_USDC`), 실행당(`PAYSH_RUN_SPEND_CAP_USDC`), 일일(`PAYSH_DAILY_SPEND_CAP_USDC`). 리소스는 allowlist로 제한되고, 모든 지출은 멱등 operation ID로 기록돼 중복 결제가 불가능하다. **자율성과 통제가 동시에 성립한다는 것 자체가 이 레이어의 주장이다.**

## 4. 왜 Solana이고 왜 USDC인가

**Solana** — 이 워크로드는 건당 금액이 작고 호출이 잦다. API 한 번 확인할 때마다 수수료가 몇 달러씩 나가면 x402 모델 자체가 성립하지 않는다. 수수료가 사실상 무시할 수준이고 확정이 1초 안에 끝나야, 에이전트가 "필요하면 확인한다"는 판단을 자유롭게 할 수 있다. 에이전틱 결제는 **저비용·고빈도가 전제**고, 그 조건을 만족하는 체인이 Solana다.

**USDC** — 협상 결과는 "50만 원어치 콘텐츠 1건" 같은 계약이다. 브랜드가 예산을 잡고 크리에이터가 수락하는 순간부터 정산까지, 가치가 변동하면 안 된다. 변동 자산으로 에스크로를 걸면 정산 시점에 다시 협상해야 하고, 그러면 자동화가 깨진다. 스테이블코인은 선택이 아니라 **자동 정산의 필요조건**이다.

## 5. 지갑을 보이지 않게 만든다 — 목표 상태

> ℹ️ 아래 네 항목은 **코드상 모두 구현됐다**(2026-08-02). 다만 배포 환경에 릴레이어 키 / 정산 서명 키 / `KNOT_USER_WALLET_PROVISION=1`이 주입돼야 실제로 동작한다. 배포 확인 전에는 "구현했다"까지만 말하고 "데모에서 증명됐다"고 하지 말 것. 상세: `docs/WALLET_LOGIN_FEE_AND_PAYSH_DECISION.md` §4.

에이전틱 커머스에서 가장 흔한 실패는, 자동화를 만들어놓고 **입구에 지갑 팝업을 세워두는 것**이다. 지갑 설치를 요구하는 순간 "사람 개입 없음"은 첫 화면에서 이미 거짓말이 된다.

KNOT이 가려는 방향은 반대다.

- **로그인은 구글 계정으로 한다.** 지갑 설치도, 시드 문구도 요구하지 않는다. ✅ *현재 성립*
- **계정을 만들면 Solana 지갑이 자동으로 따라 생긴다.** 키는 Google Cloud Secret Manager에 보관되고, 유저는 주소만 본다. ✅ *구현 완료 — 배포 시 `KNOT_USER_WALLET_PROVISION=1` 필요*
- **유저가 네트워크 수수료를 직접 관리하지 않게 한다.** 네트워크 수수료는 플랫폼 릴레이어가 SOL로 대납하는 구조다. ✅ *구현 완료 — 배포 시 릴레이어 키 주입 필요*. USDC 회수 회계는 아직 영수증에 없다.
- **원하는 유저는 자기 Phantom 지갑을 연결해 수령 주소를 바꿀 수 있다.** 커스터디는 기본값이지 강제가 아니다. ✅ *`walletCustody: PLATFORM | SELF`*

목표가 달성되면 유저 경험에서 블록체인은 복잡한 설정이 아니라 **증거로서만 남는다** — 대시보드의 Explorer 링크, 트랜잭션 서명, 검증 가능한 합의 해시.

> 정확한 표현 주의: Solana 네트워크 수수료는 언제나 SOL로 지불된다. KNOT이 하는 것은 "가스를 USDC로 내는 것"이 아니라 **"플랫폼이 SOL로 대납하고 USDC로 회수하는 것"**이다. 소개서·발표에서 이 문장을 그대로 쓸 것.

## 6. 데모에서 실제로 증명되는 것 / 아직 아닌 것

발표에서 가장 중요한 것은 구현된 것과 다음 단계의 경계를 명확히 두는 것이다.

**증명됨 (실제 트랜잭션 서명 존재, localnet)**

- 에스크로 락 → evidence 검증 → 마일스톤 릴리즈까지 완주.
- 정산 USDC가 크리에이터가 등록한 지갑 주소로 실제 이동.
- A2A 협상 4턴(`OFFER → COUNTER → ACCEPT → ACCEPT`)이 HTTP로 오간 기록.
- Agreement 해시 검증, 중복 릴리즈 멱등 처리.

**범위 한정 — 반드시 함께 말할 것**

- 위 E2E는 **localnet 라이브 서명** 기준이다. 공유 devnet 트랜잭션은 프로그램/mint 설정과 지갑 펀딩이 완료돼야 제출 가능하다.
- **현재 배포본의 정산은 완전 자율 정산으로 말하지 않는다.** 브랜드 예치와 마일스톤 릴리즈 모두 지갑 서명을 요구한다. 서버 서명 경로가 켜진 뒤에만 자동 정산으로 설명한다.
- **pay.sh 실호출 증거가 아직 없다.** 구현은 완료(allowlist·3중 지출 한도·멱등 operation)됐으나 sandbox 스모크가 미실행이다. 호출 영수증을 확보하기 전에는 Agent 운영 결제 경로가 준비됐다고만 말한다.
- **devnet 전용이다. mainnet 자산은 일절 사용하지 않는다.**
- 자동 생성 지갑은 플랫폼 커스터디다. 실서비스에는 키 로테이션·복구 정책이 추가로 필요하고, 이는 v2 범위다.

**이 경계를 지키는 것 자체가 주장이다.** 게이트웨이는 시뮬레이션 영수증을 에스크로 성공으로 인정하지 않도록 코드 레벨에서 막혀 있다. 온체인 서명이 없으면 성공이 아니다.

## 7. 발표용 30초 버전

> ⚠️ 아래 스크립트는 현재 배포 상태에 맞춰 낮춘 버전이다. 자동 정산과 pay.sh 영수증이 확보되기 전에는 더 강하게 말하지 않는다.

> 인플루언서 마케팅에서 진짜 병목은 매칭이 아니라 정산입니다. 브랜드는 선입금이 무섭고 크리에이터는 미수금이 무서워서, 사이에 항상 사람이 낍니다.
>
> KNOT은 브랜드 에이전트와 크리에이터 에이전트가 직접 협상하게 하고, 합의 내용을 해시로 검증 가능한 계약에 묶은 뒤, USDC를 에스크로에 예치합니다. 콘텐츠 게시가 확인되면 마일스톤 기준에 따라 크리에이터에게 정산됩니다. 외부 검증 API 비용은 Creator 보상금과 분리된 Agent 운영 결제로 관리합니다.
>
> 유저는 복잡한 정산 구조를 직접 다룰 필요가 없습니다. 로그인하고 계약을 확인하면, 남는 것은 대시보드의 거래 기록과 정산 상태입니다.
>
> **에이전트가 협상하고, 크리에이터가 만들고, 예치금이 정산 신뢰를 보장합니다.**
