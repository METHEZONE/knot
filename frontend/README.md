# KNOT Frontend

Next.js App Router + TypeScript frontend for the KNOT product MVP.

The app is built for Google Cloud Run. Other preview hosts are not deployment
targets for this repository.

## Local

```bash
npm install
npm run dev
```

Open `http://localhost:3000`.

## Data Mode

The v2 product flow is API-backed. Local development should use the repository
runner from the root so Firebase Auth emulator, Product API, Creator A2A, Web3
gateway, and Next.js all share the same env:

```bash
scripts/local/bootstrap_env.sh
scripts/local/dev_stack.sh
```

For frontend-only work, run Next.js with `frontend/.env.local` generated by the
bootstrap script:

```bash
npm run dev
```

Local Auth emulator test accounts:

```text
Brand    test1@knot.demo     knot-demo-1234
Creator  test3@knot.demo     knot-demo-1234
```

Google OAuth is disabled in the local Auth emulator UI path. Use email/password
for local testing and real Firebase config for Google sign-in smoke tests.

The browser calls Product API through the Next.js proxy route
`/api/v1/[...path]`; `KNOT_API_BASE_URL` stays server-side.

Implemented Product API routes used by the app include:

```text
GET  /api/v1/me
POST /api/v1/me/role
POST /api/v1/me/brand-profile
POST /api/v1/me/creator-profile
POST /api/v1/me/wallet
GET  /api/v1/brand/dashboard
GET  /api/v1/creator/dashboard
POST /api/v1/creator/availability
POST /api/v1/brand/promotions
POST /api/v1/promotions/{promotionId}/matches:run
GET  /api/v1/match-runs/{matchRunId}/candidates
POST /api/v1/match-runs/{matchRunId}:start-negotiation
GET  /api/v1/promotions/{promotionId}
GET  /api/v1/promotions/{promotionId}/activity
GET  /api/v1/negotiations/{negotiationId}
GET  /api/v1/negotiations/{negotiationId}/messages
GET  /api/v1/negotiations/{negotiationId}/agreement
POST /api/v1/agreements/{agreementId}/evidence
POST /api/v1/evidence/{evidenceId}:verify
POST /api/v1/agreements/{agreementId}/escrow:lock
POST /api/v1/escrows/{escrowId}/milestones/{milestoneId}:release
```

The browser does not construct A2A protocol messages. It consumes Product API
projections of matching, negotiation, Agreement Artifact and settlement state.
Escrow receipts display only API-returned signature and Explorer data; the UI
does not synthesize fake receipt values.

Core product routes:

```text

```

Compatibility redirects:

```text
/brand/me -> /mypage
/brand/settings -> /mypage
/creator/me -> /mypage
/creator/settings -> /mypage
/brand/negotiations/{negotiationId} -> /negotiations/{negotiationId}
/creator/negotiations/{negotiationId} -> /negotiations/{negotiationId}
```

The workspace navigation is intentionally not a numbered stepper. Role pages do
not render an internal sidebar, because onboarding is not the beginning of a
single transaction funnel. After onboarding, a Brand can create many Promotions
and a Creator can receive many agent-negotiated offers. The global header keeps
only broad navigation; `My` and `Settings` are account actions near the page
title, not deal-flow steps.

## Cloud Run Container

```bash
docker build -t us-central1-docker.pkg.dev/knot-dev-503505/knot/knot-web:local .
docker run --rm -p 3000:3000 \
  -e PORT=3000 \
  us-central1-docker.pkg.dev/knot-dev-503505/knot/knot-web:local
```

Production Cloud Run config must pass public Firebase values and API base URLs
as environment variables. Do not put service account JSON, API tokens, seed
phrases, private keys, or signer material in `NEXT_PUBLIC_*`.
